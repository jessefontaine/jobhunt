# Jobhunt — design spec

## Context

A pipeline that (a) holds a CV and a structured profile, (b) checks several Dutch job sources for
PhD / research / neuro-cogpsy roles, (c) ranks listings by fit, and (d) learns from the user's
ratings so recommendations get sharper over time. Runs are manual (`uv run jobhunt check`); a
timer is a later one-line addition.

Decisions made with the user (do not re-litigate):
- Geography: Netherlands only.
- Sources, in build order: AcademicTransfer → EURAXESS (NL filter) → named institute pages → Indeed/LinkedIn (best-effort).
- Runtime: manual CLI now; scheduling later.
- Rating UX: markdown digest, the user edits `rating:` / `note:` lines, `jobhunt rate` ingests them.
- Approach A: Python does everything deterministic; Claude (`claude -p`, headless CLI on the user's subscription) does fit-scoring and preference summarisation.

Facts checked at the time: AcademicTransfer and EURAXESS search pages are server-rendered HTML
(no RSS/API); AcademicTransfer uses a "Load more" button (its XHR inspected during impl),
EURAXESS uses `?page=N`.

*(This spec predates the engine/workspace split — see `2026-09-18-engine-workspace-split-design.md`.
Personal details from the original have been removed.)*

## Design

### Tech
Python ≥3.12 (3.14 present), `uv` project, package `jobhunt` under `src/`, console script `jobhunt`.
Deps: `httpx`, `beautifulsoup4`, `pyyaml`, `pydantic`, `typer`. Dev: `pytest`, `pytest-httpx` (or hand-rolled fake
transport), `ruff`.

### Profile (`profile/profile.md`) — seeded from the CV, then hand-edited
Sections: **Targets** (ranked role types), **Research interests**, **Methods**, **Skills**,
**Background**, **Constraints** (geography, earliest start, languages), **Dealbreakers**.

`profile/preferences.md` initial content: `## Manual\n(rules you write yourself; preserved)\n\n## Learned\n(none yet)`.

### Data model (`models.py`)
- `Listing`: `id` (sha1 of `source + canonical url`, first 12 hex), `source`, `title`, `employer`, `location`,
  `url`, `posted: date|None`, `deadline: date|None`, `summary` (list-page excerpt), `description` (detail page full
  text), `fetched_at`, `raw: dict`.
- `Score`: `listing_id`, `score: int 0–100`, `role_type: phd|postdoc|ra|industry|other`, `area_tags: list[str]`,
  `why: str`, `concerns: str`, `model`, `scored_at`.
- `Rating`: `listing_id`, `rating: int 1–5`, `note: str`, `digest: str` (filename), `rated_at`.

SQLite tables mirror these (`listings`, `scores`, `ratings`); `ratings.jsonl` is the source of truth and `store`
can rebuild the `ratings` table from it (`jobhunt rate --rebuild`).

### Sources (`sources/`)
`Source` protocol: `name: str`, `fetch(cfg, http) -> SourceResult(listings: list[Listing], errors: list[str],
manual_urls: list[str])`. Parsers are pure functions `parse_search(html) -> list[Listing]` and
`parse_detail(html) -> str` so they can be fixture-tested. Shared `http` client: fixed UA, 1 req/s, 3 retries with
backoff, 20 s timeout. Detail pages are fetched only for listings not already in the store.
- **academictransfer**: `GET /en/jobs/?q=<query>`; parse cards (title, employer, location, published, deadline,
  excerpt, link). Handle "Load more" by finding the XHR it calls (inspect during impl) or by iterating the query
  set — dedupe by id across queries. Detail: main content text.
- **euraxess**: `GET /jobs/search?keywords=…&<country facet>&page=N` until no results or page limit (5). Confirm the
  exact country facet param during impl (the guessed one returned unfiltered results).
- **pages**: driven entirely by config selectors; `employer = name`; no detail fetch unless `detail: true`.
- **indeed / linkedin**: attempt `httpx` GET with browser UA; on 403/captcha/empty → `errors=["blocked"]`,
  `manual_urls=[search url]`. Never retry aggressively; never attempt to bypass blocks.

### Scoring (`scoring.py`)
- Select unscored listings with `deadline is None or deadline >= today`.
- Prompt (system-ish preamble + JSON): `profile.md`, `preferences.md`, `cv.md` (trimmed), up to `examples` rated
  listings (all with rating ≥4 or ≤2, most recent first, capped; each as title/employer/summary/rating/note), then
  the batch as JSON `[{id,title,employer,location,deadline,description(≤3000 chars)}]`. Ask for ONLY a JSON array
  `[{id, score, role_type, area_tags, why, concerns}]`.
- Runner: `subprocess.run(["claude","-p","--output-format","json","--model",model], input=prompt)`; parse the
  outer JSON, take `result`, strip code fences, `json.loads`, validate with pydantic; ids must match the batch.
  Runner is an injectable callable so tests use a fake. One retry on parse failure; then leave unscored.
- `jobhunt score --dry-run` prints the prompt for the first batch.

### Digest (`digest.py`) — exact format
```markdown
# Job digest — 2026-09-17
New: 12 · Unscored: 1 · Source errors: euraxess (timeout) · Manual: [Indeed search](url)

## 1. PhD: Computational models of visual cortex — Donders Institute
<!-- id: a91f3c0d2e4b -->
score 84 · PhD · Nijmegen · posted 2026-09-10 · deadline 2026-10-15 · [academictransfer](https://…)
**Why:** fMRI + DNN encoding models, directly matches vision/NeuroAI interests.
**Concerns:** requires Dutch teaching after year 1.
rating:
note:

## 2. …
```
Sorted by score desc; unscored listings at the bottom under `## Unscored`; expired listings omitted. Listings rated
in a previous digest are never re-emitted. `jobhunt digest` writes `digests/<today>.md` (appends `-2` etc. if it
exists) and prints the path.

### Ratings (`ratings.py`)
- `jobhunt rate [digest_path]` (default: newest digest). For each `<!-- id: … -->` block, read `rating:` and
  `note:`. Empty rating → skip. Non-integer or outside 1–5 → report line number, skip. Already-rated id with same
  value → skip; different value → new record (latest wins).
- Append records to `data/ratings.jsonl`, upsert into SQLite.
- Regenerate `profile/preferences.md`: keep `## Manual` section verbatim; replace `## Learned` with output from
  `claude -p` given all ratings (title/employer/summary/rating/note) and the current Learned rules: "Write ≤12
  concise bullet rules describing what this person rates high vs low. Keep prior rules still supported by the data;
  drop contradicted ones." Skipped if fewer than 3 new ratings (`--force` overrides).

### `/jobhunt` skill (`.claude/skills/jobhunt/SKILL.md`)
Runs `uv run jobhunt check`, reads the produced digest, presents the top 10 in chat (title, employer, score, why,
deadline, link). If the user replies with ratings ("1: 4, 2: 2 — too clinical"), Claude edits the digest's
`rating:`/`note:` lines and runs `uv run jobhunt rate`. Never scores in-session; always via the CLI.

### Error handling
- Source failure → warning in digest header, run continues. No source ever raises out of `fetch`.
- Scoring failure → listing stays unscored, appears under `## Unscored`.
- Rating parse errors → printed with line numbers; valid lines still ingested.
- Blocked scrapers → manual URL in digest; no evasion.
- Detail fetch failure → keep listing with `description=summary`.
